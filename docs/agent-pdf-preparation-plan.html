Baseline diagnosis · Why did closing ask me to save?

A generated outline can mark the PDF as changed

When a PDF has no native or saved outline, MarkPDF can generate one for the sidebar. Applying that outline marks the tab dirty. Closing a dirty tab asks what to do with the unsaved change.

1Open PDFExisting behaviorRead document and metadata.
2Generate outlineConditionalNo existing outline is available.
3Mark tab dirtyAutomatic changeNo user edit is needed.
4Ask on closeSave decisionThe metadata has not been saved.

Optical character recognition (OCR) completion does not set that dirty flag in the inspected path. The existing PDF save also does not embed OCR text. The prepared synthetic fixture now closes without that prompt and reopens with its outline. The user's original PDF has not been reproduced.

Baseline design · How does preparation finish?

Save first, then index the final bytes once

The operation needs ownership of the exact document revision. It must coordinate with automatic background work, user saves and other windows. A successful application launch is only the start.

1 · ResolveCheck access and choose the exact document.
2 · PrepareHold automatic indexing while metadata settles.
3 · SaveWrite eligible outline changes; preserve user edits.
4 · IndexUse one owned job for the final saved bytes.
5 · ReportReturn identity, save outcome, index outcome and coverage.

The implementation uses the existing single-instance launch route and private correlated result records. Local cold/warm startup, cancellation and data-directory identity were exercised. Unacknowledged request records are retained for inspection. Fine-grained external progress is not forwarded; the final receipt and desktop progress are available.

What does the agent do if parsing is incomplete?

Use available evidence and name the missing pages

The preparation reply carries no document text. It reports readiness, separate save and index outcomes, known missing pages and the next useful action. The design also calls for coverage in search and open-document listings. The actual implementation mapping includes a shared coverage module.

ReadySearch, then read the pages supporting the answer. Cite their original PDF page numbers.Bounded retrieval
IncompleteUse the normal parser for unresolved pages or unsupported content. Disclose which parser supplied the evidence.Fallback
Needs actionExplain missing access, disabled indexing, save conflicts or unsupported automatic saves.No silent bypass
UnknownA timeout or missing result is not success. Reconcile actual file and index state before claiming completion.Do not guess

No search hits do not prove that a topic is absent. Whole-document tasks can read bounded portions or request an explicit export. Token savings must be measured; selective retrieval remains the skill's default. Actual fresh-agent compliance and token savings have not been measured.

Approved baseline · What was the build order?

Prove the desktop save before adding external launch

The cards preserve the approved build sequence and its acceptance goals. The status ledger below records what was actually exercised. Actual agent setup and usage measurement remain unverified, so these cards are not a claim that every goal is complete.

1

Save preparation-only changes

Start with a failing desktop acceptance journey, then drive ownership and the narrow exporter through focused inner tests with real PDFs.

Done when the outline persists, close needs no save prompt, and refusal fixtures remain byte-identical.

2

Connect the agent

First prove a production-equivalent launch harness. Then add cold/warm request-result transport, the command and the Model Context Protocol adapter.

Done when an external request opens the correct tab and retrieves a cited passage from the final saved hash.

3

Report incomplete evidence

Use mixed text/scanned fixtures and independently known unresolved pages.

Done when missing pages are named, available content remains usable and an agent discloses fallback.

4

Prove ownership and recovery

Exercise edits, competing saves, external replacement, cancellation and restart.

Done when failures preserve originals and distinguish a completed save from failed indexing.

5

Verify actual agent use

Set up supported clients, observe fresh sessions and compare preparation separately from warm retrieval.

Done when tool traces and the visible app prove the workflow, with measured usage and answer quality.
